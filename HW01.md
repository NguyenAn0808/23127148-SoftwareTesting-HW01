## Learning outcomes

The assignment expects the student to:

1. Describe the 2026+ QA/QC job-market landscape, including AI-augmented testing roles.
2. Distinguish QA/QC work that AI can replace, assist, or cannot replace.
3. Design test cases for one specific physical product, not a software product.
4. Ask an AI tool for an ISTQB-process mindmap and identify 3 mistakes.
5. Analyze AI-generated test cases and identify at least 3 missed edge cases.

## Requirement 1 — QA/QC Job Market 2026+ \(40 pts\)

Find **10 QA/QC job postings** published within **60 days** of the submission date.

Mandatory requirements:

- At least **3 positions** must require AI, LLM, automation-AI, or similar AI-augmented testing skills.
- For each posting, include:
  - Link
  - Dated screenshot
  - Job description
  - Required skills
  - Salary
  - 1–2 sentences of AI Impact Analysis
- Anti-cheat requirement: screenshots must show the student's job-platform login/display name in the corner.
- The displayed account name does **not** need to match the student ID.

Additional CLO activity:

- Ask an AI tool to draw or describe a QA/QC role mindmap based on ISTQB/process concepts.
- Identify and correct **3 mistakes** in the AI-generated mindmap.

## Requirement 2 — 20 Software Defects from 2022–2026 \(20 pts\)

Find **20 publicized software defects** from 2022 through 2026.

Mandatory requirements:

- At least **5 defects** must relate to AI/LLM issues, such as hallucination, prompt injection, or bias.
- For each defect, include:
  - Source link
  - Description
  - Severity
  - Consequences
  - Solution or mitigation
  - One place where AI is biased or hallucinates when explaining the defect
- The AI bias/hallucination item applies to **every defect**, so there must be **20 total identified AI mistakes or biases**.

## Requirement 3 — Test Cases for One Physical Product \(40 pts in requirements, 25 pts in final rubric\)

Choose **one specific household device** that the student owns, such as a fan, water filter, rice cooker, or smart bulb.

Product evidence requirements:

- Submit one photo of the actual device and the student ID card in the same frame.
- Declare:
  - Brand
  - Model
  - Year
  - Serial number, with the middle 4 characters masked

Test design requirements:

- Design **15 total test cases**.
- Each test case must include:
  - Objective
  - Input
  - Steps
  - Expected result
  - Actual result
  - Verdict
- Execute at least **5 of the 15** test cases on the real device.
- Record short videos of the executed test cases. Each video must be **60 seconds or less**.
- Aim to find at least **5 defects** from the real device during execution.
- Log physical-device defects as **GitHub Issues** in the student's own repository.
- Include a screenshot of the GitHub Issues page showing the student's GitHub username.

AI-missed edge-case requirements:

- At least **3 test cases** must be edge cases that the AI tool did **not** find.
- For those edge cases, provide both:
  - A screenshot of the AI conversation showing that the AI did not generate those edge cases
  - A written explanation of why AI missed them

## Mandatory AI Collaboration Protocol

This applies to all AI-assisted work in HW01. Missing any required AI-compliance item causes deductions and can forfeit the AI-compliance rubric column.

### Allowed tools and Bloom-AI level

- Students may use any AI tool, such as ChatGPT, Claude, Gemini, Copilot, Cursor, or similar tools.
- Students must declare every AI tool used.
- Faculty does not provide paid accounts.
- Bloom-AI levels for HW01:
  - **G9.1 Understand:** Ask AI for an ISTQB mindmap and correct it.
  - **G9.3 Analyse:** Find at least 3 edge cases missed by AI for the real physical device.

### AI Audit Report — required appendix

Each AI-generated artifact must have one audit entry. One batch generated by one prompt counts as one artifact.

Each audit entry must include these 5 sections:

1. **Prompt + tool:** Full prompt, AI tool name, and timestamp in `HH:MM dd/mm/yyyy` format.
2. **AI output:** Full AI output, or a red-bordered screenshot with annotations. Do not summarize or paraphrase.
3. **Verdict:** VALID, INVALID, or INCOMPLETE, with reasoning grounded in ISTQB or course materials.
4. **Reasoning:** 2–5 sentences citing the matching slide or ISTQB section.
5. **Student fix:** Corrected artifact, highlighting what changed.

At the end of the AI Audit Report:

- Summarize AI accuracy ratio using VALID / INVALID / INCOMPLETE percentages.
- Conclude when AI should and should not be used for this kind of work.

### AI Critique — required

Write a **200–300 word** critique explaining:

- Where AI was wrong, biased, or incomplete.
- Why AI failed to catch the issue.
- What principle the student learned about collaborating with AI on this homework.

### Mandatory disclosure — required

Paste this disclosure at the end of the report, before appendices, adapted to the actual submission:

```text
[Test cases / script / dataset / report] was initially generated by [AI tool name]; I reviewed and modified [section X], added [edge cases Y, Z]; [section W] was written entirely by me. The detailed AI Audit Report is attached as Appendix A. I confirm I did not use AI to generate any artifact listed in the prohibited category below.
```

### Anti-AI-cheat constraints

The following artifacts must **not** be AI-generated:

- Device photo with the student ID card in the same frame.
- Execution videos with the student's own voice narration.
- All 10 job-posting screenshots showing the student's login/username.
- Prompt log `.md` with timestamps for every AI prompt sent.

If these are found to be AI-generated, the entire homework receives 0 and is forwarded to the disciplinary board.

### Oral defense risk

A random 30% of students may be invited to a 5–7 minute oral defense after the deadline. Possible tasks:

- Run any test case or scenario live.
- Explain why one input was chosen instead of another.
- Point out one AI mistake that the student corrected.

Failing at least 2 oral-defense questions results in the homework grade being multiplied by 0.5.

## Operational notes for future work

- Treat the assignment as evidence-heavy: screenshots, prompt logs, signed forms, GitHub Issues, YouTube links, and device media matter as much as written analysis.
- Do not fabricate job postings, screenshots, salary data, defects, physical-device defects, serial numbers, GitHub Issues, videos, or prompt logs.
- If helping generate report content, preserve a clear boundary between AI-drafted text and student-owned evidence.
- Any AI-generated artifact used in the report needs a matching AI Audit Report entry.
- For Requirement 3, choose a real device early because the physical evidence, execution videos, and defect logging depend on that choice.
